# 运行时托盘

程序启动后在 Windows 通知区域注册 LucidDesk 图标。左键或键盘激活显示现有分组；右键菜单提供显示分组、新建分组、新建文件夹面板、设置和退出。显示操作沿用 pane 的现有层级设置，不修改置顶偏好。

右键菜单复用分组的 Composition 浮层：圆角、Fluent 图标和淡入/悬停动画。每次打开时读取应用设置中的主题和材质，使用与分组菜单相同的材质默认属性，不沿用自定义强度；未设置全局外观时沿用第一个面板，无面板时使用系统主题和 Mica。显示、新建和应用操作以分隔线分区，统一文字字重与对齐。菜单根据托盘所在屏幕缩放并限制在工作区内，支持方向键、Enter/Space 选择、Escape 关闭与失焦关闭；关闭后将焦点归还通知区域。

Shell 的同步通知回调只投递操作，随后由 UI 消息队列执行，并合并尚未执行的连续点击。不要在通知回调栈中直接访问应用状态或打开模态菜单：通知可能重入正在持有应用状态的 Hook IPC，嵌套菜单循环会导致状态重复借用。

托盘使用 Win32 `Shell_NotifyIconW` 和版本 4 回调，不增加依赖。图标、隐藏消息窗口及菜单资源随运行会话释放；退出发送现有 UI 消息循环的退出请求，然后执行 Hook 分离与桌面恢复。`TaskbarCreated` 消息重新注册托盘图标，但不更改已有的 Explorer/Hook 恢复策略。

系统可以将图标放进通知区域的折叠菜单；程序不修改用户的任务栏设置。

交互式 Windows 会话中执行托盘测试：

```powershell
cargo test -p luciddesk tray::tests --bin luciddesk -- --ignored
```

测试使用独立托盘图标，验证注册、版本 4 键盘回调、错误图标 ID 过滤、模拟任务栏重建后的重新注册，以及释放时删除图标。回归测试在状态被借用期间同步发送连续激活消息，确认操作延迟到借用释放后执行且重复消息被合并。它不重启 Explorer。
