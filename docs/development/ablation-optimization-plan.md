# 消融实验后的优化方案

日期：2026-09-14。状态：方案，尚未实施或验证新增优化收益。

依据：[存储层消融](history/storage-ablation-20260913.md)、[Hook 与绘图消融](history/hook-render-ablation-20260914.md)，并核对当前工作区实现。实验均为 debug 局部测量，绘图探针使用 WARP；第二轮结束后绘图代码仍有变化，历史数字只用于判断优化方向。

## 目标与优先级

保留已证明有效的三处存储保护和六项 Hook／绘图优化。后续减少缓存命中时仍在重复执行的工作，并检查真实刷新、滚动和 DPI 切换是否导致不必要的缓存重建。

| 顺序 | 工作 | 类型 | 进入实现的依据 |
| --- | --- | --- | --- |
| 0 | 在当前冻结快照上更新基线和工作量计数 | 验证 | 旧结果不能覆盖后续源码修改 |
| 1 | 配置值规范化，提高保存快速检查的命中率 | 小范围实现候选 | 等价输入仍需 TOML 克隆、修改、解码和序列化 |
| 2 | 检查刷新后的像素身份及跨帧纹理复用 | 先验证、再修复漏失效或误失效 | 纹理重复上传的代价显著；当前已有像素复用实现 |
| 3 | 减少 Hook 命中查询中的集合分配和完整排序 | 分开实施两个候选 | 热查询仍构造 BTreeSet/Vec 并排序，缓存本身应保留 |
| 4 | 减少文字布局缓存查询时的字符串分配 | 小范围实现候选 | 当前 `layout_scaled` 在查询前执行 `text.to_owned()` |
| 5 | 按实测决定事务入口、缓存局部失效、LRU 淘汰改造 | 待补测 | 现有实验未测出这些具体路径的收益和失效成本 |

排序结合实现风险与可验证性，不代表已确认的全应用耗时排名。

## 存储：让等价配置更早返回

位置：`crates/desktop-storage/src/store/config.rs`、`codec.rs` 和 `store/mod.rs`。

实验中完全相同的配置保存约为 0.2 微秒，等价配置约为 150.2 微秒，说明避免落盘之后仍有序列化成本。拟为常见配置构造统一的解析和规范化入口，优先覆盖 `pane_options`，再依据真实调用频率扩展到外观设置。

具体约束：

1. 保留原始值完全一致时的快速返回；对其余输入先按已有规则校验和规范化，再与已解码的当前值比较。
2. 明确区分数值等价和文本相同，例如 `6`、`6.0`、`6.000`；遵守现有精度、默认值、缺省字段和兼容输入规则，不随意将持久化 f64 降为 f32。
3. 批量更新必须遵守原来的顺序、重复键和错误处理语义。非法输入不能因后续覆盖或“最终值相同”被静默接受。
4. 保留 `source == self.source`、外部文件冲突检查、原子写入和 SQL 条件更新。规范化只增加提前返回的机会，不取代后续保护。
5. 复用现有解析规则，避免另外维护一套容易漂移的校验器；若必须大规模复制解析逻辑，先缩小到调用方统一编码这一方案。

验收：完全相同和等价配置均零写盘；等价输入不进入整份 TOML 克隆／序列化路径；实际变更正常写入；无效值拒绝、外部编辑冲突、注释保留、失败恢复及批量更新语义均通过。比较新增规范化本身的成本后再决定是否保留，不承诺达到 0.2 微秒。

未变工作区保存的约 552 微秒还包含事务和 SQL 查询。先测调用次数与触发来源；只有发现高频无变更保存，才在明确的应用状态变更入口避免重复调用。不要直接给 `WorkspaceStore` 加一个“上次 Workspace 相同就跳过”的缓存，这可能遗漏独立选项更新、导入、恢复或重新加载。

## 绘图：保持资源身份，缩短命中路径

位置：`app/src/pane/folder/images.rs`、`assets.rs`、`render.rs`、`label.rs`、`native_graphics.rs`。

**图标复用先验收现状。** 当前文件夹图片路径已有内容哈希、像素比较及 Arc 复用，Renderer 也保留跨帧纹理并回收视口外资源。先测刷新相同目录、离开后返回、滚动往返及单个文件变化时的命中情况；若刷新产生了内容相同但身份不同的像素，再修复对应来源，不再增加另一层全局缓存。

验收重点：稳定视口预热后零重复上传；未变目录刷新保持像素身份；单个图标变化只上传受影响资源；DPI／图标尺寸变化正确重新采样；同帧共享图像仍只上传一次；哈希碰撞不能混淆内容；缓存条目和字节数受控。滚动时允许按现有回收策略重新上传已淘汰资源，不要求缓存整个大目录。

**文字布局优化命中成本。** 保留布局缓存及文字格式缓存，优先尝试按尺寸、DPI、行数和字号分组后用借用的 `&str` 查询，或提供等价的借用键查找，避免每次命中都分配 String。所有影响布局的参数继续参与键比较；只有插入新条目时复制文字。先比较分配次数、命中耗时和整体布局耗时，再选择实现，避免为微小收益引入复杂键结构。

验收：原探针 1,200 次预热调用不重建布局；新增命中路径不复制标签字符串；宽度、DPI、字号、文本和行数变化能触发正确布局；三个 DPI 的像素、换行、裁剪、阴影和省略号行为不变。

**GPU 设备复用保持现状。** 已有 UI 线程缓存和设备移除检查，本轮没有新增设备管理层的依据。后续补测多窗口生命周期、设备失效后的重建及长期资源稳定性；不为减少一次检查而移除设备健康检查。

## Hook：减少候选处理成本

位置：`crates/desktop-hook/src/geometry/cache.rs`。

保留命中缓存、空间桶及重绘区域缓存。关闭命中缓存后每轮增加 255,960 次原生查询，说明这里首先要避免破坏已有快速路径。

按两步独立对照：

1. 候选去重：比较现有 BTreeSet 与收集到 Vec 后排序去重的成本。保留长矩形的 broad 路径、负坐标、跨桶覆盖及大查询区域回退。先使用局部容器，不直接引入可重入消息处理中共享的可变缓冲区。
2. 命中选择：在候选集合已确定后，尝试筛掉不可见或不包含查询点的项，再单遍选择最小 `(距离平方, item)`，减少完整排序。保持图标先于标签的标志选择，以及等距项目的原索引规则；重绘候选顺序单独保留。

验收：与原算法对照负坐标、重叠矩形、超长标签、等距点、隐藏项和空白区域，结果及标志一致；预热命中仍零原生几何查询；选择变化仍及时失效；原生 ListView 探针通过。分别测小规模、81 项和更大集合的 p50/p95，只有收益跨轮次可复现时才采用。

## 暂缓的结构性改造

以下均是待验证候选，消融实验没有证明它们优于当前实现：

- **Hook 局部失效。** 当前单项几何变化会清除命中和重绘索引。先统计单项变化后的重建次数；若成本集中于此，再比较增量更新。需要同时处理旧／新矩形、选择文字范围、排序、隐藏成员及布局代际；不延迟本应立即生效的失效通知。
- **布局 LRU。** 当前超过 1,024 项时扫描寻找最久未使用项。先跑超过容量的标签切换和滚动负载；仅在淘汰扫描成为热点时更换数据结构，并维持容量和淘汰语义。
- **工作区事务入口。** 先观察事件触发频率及真正变更率，再决定调用方变更标记或窄范围更新；写入失败后不能提前清除变更标记。

## 实施与验证节奏

每个候选独立提交：先记录当前基线，再引入一个改动，执行相关功能测试与同负载对照，最后更新结果。避免同时改缓存键、失效和数据结构，使收益或回归难以定位。

第一批建议为“配置规范化”和“图标复用现状验收”；第二批为“Hook 候选处理”和“文字缓存借用查询”；结构性改造依据新增测量再排期。

实验工具先补齐：支持 debug/release、WARP/硬件后端；存储实验采用与第二份实验一致的分轮执行；记录原始样本、工作量计数、缓存容量和源码哈希。开发期依据操作计数守住行为，耗时比较在同机同负载下进行，不把历史微秒值写成通用 CI 阈值。

收益分为两类验收：功能必须通过；性能需要重复对照。相同输入下保持零重复写入、布局构建或纹理上传等明确不变量；需要重建的变化路径必须正确更新。若耗时差异处于波动范围，或复杂度与内存成本明显上升，则保留原实现并记录无结论。
