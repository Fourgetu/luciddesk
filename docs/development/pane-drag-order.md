# 面板层级与菜单交互

Windows 11 x64 为主要验证平台。

## 行为约束

普通分组和文件夹面板共用 `window::create`；搜索面板使用独立窗口，并复用 `borderless_proc` 与 `set_layer`。普通分组和文件夹窗口由 Shell 拥有，搜索窗口还拥有独立的原生 EDIT 输入框。

- 未置顶面板点击或拖动时，只在桌面面板之间抬高，避免盖住普通应用。
- 打开、关闭面板菜单及子菜单，不应把下面的面板抬到当前面板上方。
- 搜索输入框跟随所属面板的层级与置顶状态。全局搜索快捷键保持桌面层级，不承担跨应用前置功能。
- 托盘“显示面板”通过 `raise_once` 一次性前置，保留原有置顶偏好；后续应用仍可覆盖普通面板。

## 实现

仅处理 `WM_MOUSEACTIVATE` 无法覆盖已经激活、但被其他面板遮挡的情况。低层 subclass 同时处理点击、非客户区点击和进入移动循环，调用 `raise_among_peers`，避免依赖模型回调的借用状态。

`desktop_insert_after` 查找可见且未关闭的桌面面板，确定插入位置。位置已经正确时不再调用 `SetWindowPos`；没有其他面板时保持当前位置，初次设置层级才允许使用 `HWND_BOTTOM`。这也减少重复点击造成的重排和闪烁。

共享 owner 的窗口可能被系统成组重排。显式抬升及菜单定位使用 `SWP_NOOWNERZORDER`；`WM_WINDOWPOSCHANGING` 忽略系统触发的被动、非激活重排。菜单自身仍使用 topmost，以显示在置顶面板上方。

搜索 EDIT 是独立的 owned popup，点击不会经过面板 subclass，因此输入框调用相同的 `raise_among_peers`。输入框自己的重排受所属面板约束；面板位置或置顶状态变化时同步输入框，仅在状态或相对顺序不一致时调整。

## 验证与边界

窗口回归覆盖共享 owner、重复点击不重排、被覆盖后的点击与拖动、菜单及两级子菜单反复打开关闭、应用窗口上层约束，以及置顶切换。搜索回归使用实际搜索窗口和原生输入框，验证已聚焦输入框的点击、全局快捷键保持桌面层级、输入框随面板置顶和取消置顶。

原生搜索和渲染测试应隔离进程运行。自动发送窗口消息不能替代鼠标操作验收；重叠窗口、菜单与跨应用切换需实机检查。
