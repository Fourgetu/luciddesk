# Hook 性能优化记录（基线 269831c）

> 历史记录：以下结果对应原记录日期和当时的代码、系统映像。旧探针与启动入口可能已删除；当前命令见[构建与验证](../build.md)，当前边界见[架构说明](../architecture.md)。

本轮保留矩形命中、原生源项／无操作抑制、可见插入边界、OLE 坐标和 5 个物理像素的分组间隔。未恢复曾被拒绝的网格快捷命中方案，也没有在整个按住鼠标期间暂停场景同步。

## 实现

1. 以不可变引用计数快照缓存可见顺序和前后边界；有效快照只读取一次原生位置与显示器归属。
2. 将实际图标与文字矩形放入 128 像素空间桶，仅按原距离／索引规则排序候选，保留命中标志。构建失败或失效时回到完整扫描，覆盖长矩形和负坐标。原生分组实验当时因逐帧映射变化保留扫描。
3. 缓存原生脏区，同时索引原生与显示矩形；先筛候选，再保留精确 GDI 区域相交检查，失败时仍扫描。
4. 混合桌面无原生分组裁剪区域时，避免逐项 SaveDC/RestoreDC 及额外后绘制请求，隐藏绘制拒绝和有需要的裁剪仍执行。
5. 将重复控制端定时同步合并到 100 ms。显式操作、脏场景、图标加载、身份核验和按钮释放仍及时处理。

完整拖放日志改为显式编译特性 `drag-trace`，因为 Explorer 不会继承新控制进程的环境变量。正常构建关闭该特性。

## 失效规则

场景发布、成员更新、同数量身份核验、列表结构、排列、间距、图像列表、文字、视图／字体／主题／DPI／显示器变化、滚动、释放／捕获变化和原生 Drop 完成都会触发相应失效。

选择、焦点和重绘使文字几何失效，其他有效缓存仍可使用。原生调用在 STATE 借用之外进行，以修订号避免发布跨越变化构建的缓存。绘制与输入前的身份扫描继续保留。

## 当时的验证结果

- 9 项 Hook 测试通过，包括隐藏／多选拖动顺序穷举和重叠、负坐标、长矩形覆盖。
- 3 项混合控制端测试通过，涵盖紧急同步与重复定时同步。
- 独立虚拟 ListView 的原生像素、局部重绘、缓存预热后同数量排序、选择失效、隐藏隔离和 OLE 转发通过。
- 1,580 次预热图标命中不发出 `LVM_GETITEMRECT`/`LVM_GETITEMPOSITION` 查询。
- 一次本地 Debug 夹具的 79 项批次中位数为 234.6 微秒，P95 为 329.2 微秒；不能换算为真实桌面帧率。
- 预热后的重复局部 `WM_PAINT` 不产生几何查询；重复隐藏标记查询不重建原生顺序。
- 启动后只读审计的 78 个可见图标命中全部一致，总数为 81、收纳数为 3；正常运行关闭审计。
- 当时跨进程几何、无效事务隔离、存活监测、全部目标／特性 Clippy 与诊断特性测试通过。

真实 Explorer 拖动仍需交互确认。历史基线二进制位于本地忽略目录 `target/perf-269831c-*`，源码基线为 `269831c`；自动探针未移动桌面文件。
