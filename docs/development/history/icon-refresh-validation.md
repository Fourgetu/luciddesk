# 分组图标刷新验证（2026-09-11）

> 历史记录：以下结果对应原记录日期和当时的代码、系统映像。旧探针与启动入口可能已删除；当前命令见[构建与验证](../build.md)，当前边界见[架构说明](../architecture.md)。

## 后续发现：C 盘回收站图像缓存过期

早期 E 盘验证不能证明所有驱动器行为一致。后续复现为：回收站存在一个 C 盘 APK，面板仍显示空图标。实际桌面权限下，新进程通过 `SHQueryRecycleBinW` 得到 1 项、51,140,131 字节，但新建 `IShellItemImageFactory` 仍返回空图像。通知已送达且身份正确，重复提取不能解决缓存问题。

修正改为查询跨驱动器总项目数，根据空／满状态使用 `SHGetStockIconInfo` 定位系统资源，再提取 128 像素图标。工作在现有通知工作者上执行，不新增轮询，不重载无关图标；查询失败向上传播，不假装回收站为空。

参考：[项目数量接口](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shqueryrecyclebinw)、[系统图标接口](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shgetstockiconinfo)。

## C 盘跟进验证

已有回收站项目得到满图像，启动 GPU 上传指纹为 `ca04536a3a78cc65`。增加一个自有零字节临时文件后数量由 1 变 2，字节数不变；只恢复该临时文件后数量由 2 变 1。两次通知只刷新回收站，状态保持满，未替换相同像素的 GPU 图像。原有 APK 未修改，自有文件已核对并清理。

本地日志为 `target/recycle-stale-factory.log` 和 `target/recycle-state-fixed.log`。修正后应用测试 64 项通过、3 项跳过；新增回归核对 128 像素透明空／满图像不同，既有 GPU 测试核对同身份替换图像。

为保留原有回收站内容，本次没有重做真实空／满转换。此结论取代早期“已普遍验证正确”的表述。
