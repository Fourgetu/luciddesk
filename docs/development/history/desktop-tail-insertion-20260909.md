# 桌面尾部插入边界修正（2026-09-09）

> 历史记录：以下结果对应原记录日期和当时的代码、系统映像。旧探针与启动入口可能已删除；当前命令见[构建与验证](../build.md)，当前边界见[架构说明](../architecture.md)。

## 问题与第一轮修正

报告场景有 81 个 Shell 项目，原生索引 57、58 被收纳，单元格为 112 × 147，每列 14 行。最后可见项目是索引 80“新手盒子”。部分中间空隙没有插入标记，前面的图标不能稳定拖到最后一项之后。

两条路径存在分歧：

1. `CLVView::v_OnInsertMarkHitTest` 先对未过滤原生网格运行，Hook 随后才改返回索引。该映像在返回前已抑制源项及相邻无操作位置，相关比较约在 RVA `0xac4d0`；一旦返回 -1，修改索引不能恢复合法可见空隙。
2. OLE `Drop` 曾在绕过几何 Hook 的坐标上额外合成 `DragOver`，再强制尾部标记。这会在释放时替换预览已缓存的目标，日志显示预览尾部标记与提交输入点不同。

修正将可见单元格先映射到原生单元格，再调用原生函数，由原生代码继续决定源项、无操作规则及前后标记。映射排除已收纳身份、尊重显示器边界，并将尾部空白映射到最后可见项目的原生格子内。

OLE `DragEnter`、`DragOver`、`Drop` 保持原始屏幕坐标，提交时不额外合成 `DragOver`、不强制尾部标记。原生分组实验的旧回退当时仍存在，不作为当前主线策略。

首轮记录：6 项 Hook 单元测试通过；独立原生夹具的 79 项图标／文字命中、局部重绘、选择隔离、同数量排序、插入矩形和分离通过；跨进程事务与存活监测通过。只读桌面审计覆盖 79 项命中、158 个前后插入查询，包括索引 77–80，但没有模拟实际拖动源。

## 隐藏项作为标记锚点

后续实际拖动在收纳 3 项、其中包含索引 80 时复现。832 次插入调用均完成匹配与转换，最后命中可见项 79，Shell 实际保存的标记却是 `80:0x80000000`，即隐藏项 80 之前；原生矩形为 `[560,1467,672,1474]`。

这说明 Shell 在命中返回后还会规范化边界，仅恢复输入坐标映射不能修复显示。隐藏锚点没有紧凑呈现位置，需要将其之前的可见槽位数转换为当前显示器上的紧凑边界。

这一阶段只修正标记几何，保留 Shell 保存的索引、标志、原生选择和 OLE 坐标。独立夹具以 9 种首部、中间、换列、尾部隐藏锚点核对未 Hook 的原生参考矩形，并检查标志未被绘制过程改写。

## 显示与提交共享边界解析

后续使用 `VisibleOrder` 同时解析绘制边界和提交目标。与隐藏项相邻的空隙定位到下一可见身份之前；没有可见后继时，定位到当前显示器物理末项之后。

物理末项与最后可见项不同：`CListViewHost::GetInsertMark` 会先将 after 标记索引加一，再转回 Shell 身份。仅选择最后可见项之后，可能再次指向隐藏后继。

插入 Hook 规范化合法命中，OLE 代理在转发 `Drop` 前复核缓存标记；不重新执行 `DragOver`，不改指针坐标，不替代图标命中与选择。普通可见空隙和原生无操作标记保持原处理，顺序来自当前场景而不是排序前缓存。

后续验证覆盖 5 项集合所有隐藏／选择子集、多选拖动顺序、显示器边界，以及向记录接收端转发的真实 OLE 代理。9 类边界核对规范化身份、原坐标和标记几何，8 项单元测试及原生夹具通过，临时逐命中日志已移除。

上述均为分阶段历史结果，不累计为当前测试总数。物理 Explorer 拖放仍需交互确认。只读审计开关为 `LUCIDPANE_HIT_AUDIT`，正常运行关闭。
