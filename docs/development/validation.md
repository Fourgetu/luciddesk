# 验证与兼容边界

本页说明当前实现的验证方法和限制。构建及测试命令见[构建与验证](build.md)；每次提交应记录本次执行的检查，不将历史测试数量作为当前验收结论。

## 验证分层

| 范围 | 必须检查的行为 |
| --- | --- |
| 模型与存储 | 成员归属、标签约束、配置解析、事务保存、备份恢复与无效数据保护 |
| 桌面过滤 | 收纳与释放、刷新、改名身份交接、控制进程异常退出恢复、旧组件占用保护 |
| Shell 菜单 | 鼠标和键盘打开、命令执行、重命名、打开方式、属性窗口、取消及第三方扩展 |
| 图形与窗口 | 深浅主题、材质回退、DPI、选择和焦点、层级、首帧显示与退出释放 |
| 多语言 | Fluent 键与参数、语言选择、字体覆盖、热切换状态保留及布局溢出 |
| 发布包 | EXE/DLL 同次构建、校验值、安装范围、快捷方式、升级、卸载及配置保留 |
| MSIX | 标记分流、真实包身份、LocalState DLL 加载、缓存修复、运行中更新和卸载清理 |

自动检查与实际桌面操作分开执行。原生 COM、图形、菜单和窗口测试按[构建指南](build.md)隔离进程运行，避免共享桌面与 STA 生命周期相互影响；组合运行的成功或失败不能替代单项问题分析。

## 平台边界

- Windows 11 x64 为主要验证和维护平台；Windows 10 有用户实机反馈，但并非每次提交都在全部 Windows 10 构建上验收。
- 桌面过滤依赖运行期探测的 Shell 视图接口，Win11 精简菜单使用私有 Presenter 接口。系统更新后需要重新检查能力和命令行为。
- ARM64、远程桌面、多显示器热插拔及混合 DPI 需要对应环境的验证，不能由单机启动成功推断完整支持。
- 七种语言资源有自动解析与布局检查，译文仍需要母语审校；离屏渲染不代表真实输入法、重命名或系统菜单交互已经验收。
- 第三方 Shell 扩展可以阻塞或改变菜单行为。菜单闪烁、忙碌指针、所有属性窗口组合和原生测试混跑仍需持续排查。
- MSIX 侧载验证不等同于 Microsoft Store 分发验证；App Installer、商店自动更新和各系统版本需单独覆盖。

## 记录与复现

报告包含源码提交、构建配置、Windows 版本、包类型、复现步骤、实际结果和未覆盖范围。原生菜单测试既检查消息路由，也检查最终文件操作；资源释放测试检查 Explorer 中的模块及文件占用。

崩溃分析保留同次构建的 EXE、DLL 和 PDB，日志、转储和临时测试产物留在本地 `target` 或报告附件中。数据与隐私要求见[贡献指南](../../CONTRIBUTING.md)。
