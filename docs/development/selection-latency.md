# 选择与刷新时序

更新：2026-09-26，按当前主线源码核对。`app/src/pane/hybrid.rs` 管理同步顺序，`hybrid/audit.rs` 封装后台审计，`hybrid/inventory.rs` 处理清单合并，`hybrid/icons.rs` 处理图标加载和刷新。当前使用成员过滤协议，不再发布几何布局。

## 选择互斥

普通 Pane 输入记录 `GetMessageTime`，在没有活动菜单时通过 `FilterSession::clear_selection` 请求清除真实桌面的选择与焦点。该入口使用过滤 IPC 请求，并等待处理结果；旧版异步注册消息的说明不再适用于当前主线。

反向清理由 Hook 的桌面输入通知触发。控制端核验桌面 HWND，并比较事件时间与最近的 Pane 输入；活动菜单期间或陈旧通知不清除 Pane 选择。时间比较处理 32 位计数回绕。嵌套回调暂时借用模型时保留通知，由后续 tick 重试，只重绘选择或焦点发生变化的面板。

独立 Shell 菜单使用自身的选中集合。菜单、预览和改名事务期间暂停普通清单消费与同步，避免中途覆盖正在操作的身份。

## 后台清单与过滤发布

- 常驻 STA 工作者最多处理一个在途审计。初始间隔两秒，连续无变化后退避为 4、8 秒，上限 8 秒；发现变化重置为两秒。Shell 变化通知触发优先核对，读取期间到达的通知不会随旧结果消费而丢失。
- 工作者比较原生视图修订、独立来源 PIDL 集合和分组成员键，只在变化或强制刷新时读取完整元数据。
- 清单合并可见桌面项目与独立来源中的已有分组成员；不完整快照、重复身份和枚举失败不会作为成功的删除结果提交。
- 请求与结果携带成员修订键，包含稳定身份和 Shell 解析名。改名后即使文件 ID 不变，也会拒绝使用旧路径的在途结果。
- 成员身份只在发送审计请求或收到结果时构造，不在每次普通 tick 中复制并格式化。
- 仅将图标已加载的分组成员写入完整过滤名单。名单未变化时避免重复发布；距离上次同步 30 秒时保留一次完整重发修复。
- 最近移出的图像最多保留 64 项、8 MiB、30 秒，超限先淘汰最早移出的项目；变化通知提前失效，正在分组中使用的图像不参与闲置淘汰。过滤同步成功后清除已移出项目的失败重试记录；初次加载及刷新结果均按当前成员集合接收，相同像素不替换共享图像。
- Hook 的列表变化通知触发重新过滤，一秒定时器补查遗漏变化并监测控制端存活。

上述间隔是实现中的调度条件，不代表严格的实时期限或性能测量。通知缺失时，清单变化可能等待约 8 秒才被发现；Hook 的一秒重滤和控制端存活检查不受影响。旧版每八项让步、同步双清单验证及坐标核对不再属于当前流程。

已有测试覆盖改名修订键变化、已收纳成员合并、改名提交后的异常补偿，以及退避、在途通知保留、图像回收和迟到结果处理。实际执行记录见[验证记录](validation.md)，原生视图回归见[过滤验证](../desktop-view-filter-verification.md)。旧几何探针及其延迟数据不能用作当前后端的验收结果；本轮未重新测量真实桌面 CPU、进程内存或交互延迟。
