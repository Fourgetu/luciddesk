# Rust API 与资源生命周期约定

本文规定当前实现的模块边界和资源管理方式。目录归属见[目录结构](structure.md)，检查命令见[构建与验证](build.md)。

## 领域与存储接口

- `desktop-core` 管理身份、几何、外观、项目、面板和工作区，不依赖窗口生命周期。
- 面板内容来源由互斥的来源类型表示；尺寸创建与修改均执行模型校验。
- `desktop-storage` 负责配置解析、数据库事务和备份。存储错误向调用方传播，失败时保留可恢复状态。
- 模块入口负责声明与重导出，具体实现放在所属模块；不要在多个 UI 入口重复实现身份或持久化规则。

## COM、OLE 与窗口资源

`ShellApartment` 必须通过初始化入口创建，不能跨线程传递。每次成功的 OLE 初始化都有对应释放，依赖它的窗口、菜单、拖放和 COM 对象先于 apartment 销毁。

应用运行作用域按“OLE 守卫 → GraphicsLifetime → 应用状态及窗口”的顺序声明，退出时按相反顺序释放。图形缓存通过显式清理入口释放，不留到进程退出时的线程局部析构。清理时先从 `RefCell` 取出对象，再执行可能重入的原生释放操作。

Shell 调用、菜单循环和同步窗口消息可能重入应用。调用这些入口前释放模型或应用状态的可变借用；需要后续操作时使用已有的延迟消息机制。后台工作者只传递可在线程间共享的数据，COM 对象留在所属线程。

## Windows 绑定边界

不同版本的 Windows Rust 绑定即使使用相同 ABI，也不是相同 Rust 类型。图形接口转换集中在 `native_graphics.rs`，通过 QueryInterface 获取独立引用，不能把借用指针当成所有权转移。

`unsafe` 入口应说明句柄、线程、内存和接口类型的前提。生成绑定由工具维护，局部允许必要的 Windows ABI 命名，不手工修改生成文件。

## 修改后的检查

对改动涉及的模块运行测试，检查错误返回、取消、窗口销毁和进程退出等路径。会激活原生窗口的测试按说明独立运行。检查要求见[验证与兼容边界](validation.md)；测试结果与实机结论记录在对应提交或问题报告中。
