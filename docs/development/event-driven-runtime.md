# 事件驱动的后台调度

## 调度方式

Runtime 按事件和截止时间调度工作。Shell、目录、后台结果、配置写入和窗口生命周期通知负责唤醒；每次处理结束只为最近截止时间安排一次计时器。

| 工作 | 当前触发方式 |
| --- | --- |
| Explorer 菜单 STA | 请求入队后触发内核事件，同时等待 Windows 消息；退出显式唤醒。没有待清理旧宿主时无限等待，有遗留对话框时才保留每秒清理 |
| 显示器布局 | Runtime 接收显示、设置、DPI、恢复电源与 TaskbarCreated 通知；面板 DPI 通知转发给 Runtime。变化后按两秒稳定窗口重新核对，空闲时等待通知 |
| 备份 | 存储成功写入后发送合并通知，未变化和失败写入不通知；后台完成结果直接消费。自动备份按静默十秒与备份间隔共同安排截止时间 |
| 桌面审计 | 通知优先；无变化检查保持 2、4、8 秒退避，在途请求不重复安排审计 |
| 过滤与缓存回收 | 名单变化时发布，遗漏重滤由 Hook 的一秒检查负责；控制端只发布发生变化的名单。闲置图像按最早过期时间回收；菜单结束通知接续工作 |
| 自动隐藏 | 鼠标进入、离开、非客户区、窗口位置变化及交互结束重新核对；展开 120 ms、收起 600 ms 单次确认，稳定后停止计时 |
| 连接和窗口恢复 | 窗口销毁及 TaskbarCreated 主动唤醒；断连后按 250 毫秒至十秒退避重试，正常保留三十秒维护兜底；热键冲突按十秒截止时间重试 |

所有 Shell/COM 操作仍留在原所属线程。菜单等待事件的句柄由工作线程共享持有，关闭请求先入队再唤醒，防止等待期间关闭句柄或退出丢失。配置回调只投递消息，不同步重入存储或 PaneApp。图标/审计回退、备份及图像过期共用截止时间调度，不能单独删除这些期限。

DLL 内的一秒看门狗继续保留：它同时承担控制端失联恢复、遗漏重滤和事务重绘解锁。菜单准备/取消的有界回复等待、动画、目录监听失败重试仍保留。


成员请求在途时，控制端安排短间隔检查确认；不阻塞 UI 等待整批桌面更新完成。细节见[选择与刷新时序](selection-latency.md)。
