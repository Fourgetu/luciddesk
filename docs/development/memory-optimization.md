# 图标内存管理

图标数据经过 Shell 加载、CPU 像素共享、缩放和 GPU 上传。各层分别控制复用与释放：相同像素可以共享，但仍被项目列表或窗口模型持有的数据不会因缓存淘汰立即释放。本文说明这些边界；绘制与呈现流程见[绘图与绑定](rendering.md)。

## 缓存层与所有权

以下源码路径相对 `app/src/pane/`，上限是当前实现常量。

| 层 | 入口 | 持有方式与上限 | 释放或失效条件 |
| --- | --- | --- | --- |
| 全局 CPU 像素去重池 | `image_pool.rs` | 最多 4096 条弱引用，跨桌面分组和文件夹来源共享 | 不延长像素寿命；满池时按节流策略清理失效弱引用 |
| 文件夹图像缓存 | `folder/images.rs` | 每个缓存实例默认 64 MiB、4096 项，强引用像素 | 按最近使用淘汰；身份或元数据不符时失效 |
| 桌面闲置图像 | `hybrid/image_retention.rs` | 最多 64 项、8 MiB，保留移出成员的图像引用 | 移出 30 秒后回收，超限先淘汰最早移出的项目，变化通知可提前失效 |
| 线程内 CPU 缩放缓存 | `scaled_icons.rs` | 每个绘图线程最多 128 项、2 MiB；弱引用源图像、强引用缩放结果 | 按最近使用淘汰；插入时清理失效源，超大单项不缓存 |
| GPU 位图 | `render.rs` | 各渲染上下文管理，图标保留视口及相邻一行；选中状态纹理最多 64 项 | 随驻留范围和上下文生命周期释放 |

文件夹的父子来源可共享同一个缓存实例；不同映射的缓存仍可通过全局像素池共享内容。上述数字不是整个进程的内存预算，不能直接相加：既存在共享引用，也存在缓存之外的活跃项目、缩略图、元数据和图形设备资源。

## 原始像素去重

桌面分组与文件夹加载结果调用 `image_pool::intern`：

1. 在锁外按宽、高和像素内容计算哈希。
2. 持有池锁查找弱引用，升级成功后再次比较尺寸和全部像素。
3. 内容完全一致时返回已有 `Arc<Pixels>`；哈希碰撞时保留正确的新图像，不替换成其他内容。
4. 有容量时登记新弱引用；满池且无法腾出位置时仍返回加载结果，不阻止图片显示。

弱引用条目的数量与存活像素数量不同。最后一个强引用释放后，像素缓冲可释放，池里的失效条目可以留到后续清理。满池时不会对每张新图都扫描全部条目。

文件夹工作线程不持有文件夹缓存锁进入共享池，避免扩大嵌套锁范围。共享像素按不可变数据使用；修改图像必须产生正确的新内容，不能让其他持有者看见意外变化。

## 内容有效性与预算计费

### 文件夹缓存

恢复缓存时校验 Shell 身份、修改时间、是否为文件夹和文件大小。未知修改时间不能证明内容未变，因此不直接复用。加载失败不写入空图像缓存，保留后续重试机会。

字节预算按像素 `Vec::capacity()` 计费，包含预留但未使用的空间。同一像素被多个条目引用时仍按条目保守计费，不因去重而放大缓存上限。单张图超过预算时可以继续由项目使用，只是不进入缓存。

### 桌面闲置缓存

活跃分组成员不参与闲置淘汰。项目移出分组时记录释放时间，普通维护不延长期限；快速移回时取消闲置记录并复用图像。清单或图标变化通知可使闲置内容提前失效，活跃图像走原有定向刷新路径。

回收按最早过期时间接入运行时调度，菜单或预览暂停期间可能延后执行，因此 30 秒是回收条件，不是严格的释放时限。移除缓存引用后，其他强引用仍可能继续持有像素。

### 缩放与 GPU 缓存

缩放键包含源对象地址和目标物理尺寸，命中时还核验弱引用指向同一个源对象，防止地址复用命中旧结果。同尺寸直接复用原图；其他尺寸沿用 WIC 缩放和预乘透明度处理。

缩放结果仅在同一绘图线程中共享。CPU 像素共享不代表跨窗口共享 COM 位图，也不扩大 GPU 纹理驻留范围。源图像失效后，旧缩放结果不会再次命中，但可能留到后续插入清理或缓存自身释放。

## 验证

按修改的缓存层分别执行检查，环境准备见[构建与验证](build.md)：

```powershell
cargo test -p luciddesk --bin luciddesk image_pool --locked --offline -- --test-threads=1
cargo test -p luciddesk --bin luciddesk pane::folder::images --locked --offline -- --test-threads=1
cargo test -p luciddesk --bin luciddesk image_retention --locked --offline -- --test-threads=1
cargo test -p luciddesk --bin luciddesk scaled_icons --locked --offline -- --test-threads=1
```

确认每条过滤命令实际匹配到测试；修改模块路径后同步命令。自动检查重点包括：

- 跨线程和独立文件夹来源加载相同内容时共享像素，单项刷新不改变其他图像。
- 哈希碰撞不替换内容，池满不阻止加载，最后一个强引用释放后像素不被去重池保留。
- 字节预算包含预留容量；超限淘汰顺序、未知修改时间和加载失败处理正确。
- 桌面成员移出再移回、到期、超限和通知失效，不误删活跃图像。
- 相同尺寸复用缩放结果，源内容改变后拒绝旧缓存，缩放缓存不延长源图像寿命。

跨线程去重测试比较的是共享对象与像素分配量，不是进程工作集或 Private Bytes 的实测降幅。真实收益取决于图标重复程度，不同内容的缩略图不会因去重减少。

## 内存问题排查

先固定包版本、目录内容、窗口数量、DPI 和操作步骤，再分别观察首次加载、重复访问、滚动、关闭面板及等待闲置回收后的状态。

1. 确认增长来自原始像素、缩放结果、GPU 资源还是项目元数据。
2. 检查项目列表、后台结果和窗口模型是否仍持有强引用，不能仅凭缓存条目被移除就断言资源已释放。
3. 区分活跃图像和闲置图像；文件夹 LRU 上限不约束项目列表持有的全部缩略图。
4. 分别记录像素分配量、工作集、Private Bytes 和 GPU 指标；跨层指标不直接换算。

资源生命周期规则见[Rust API 与资源约定](rust-api-review.md)，通知与回收期限见[后台调度](event-driven-runtime.md)。
