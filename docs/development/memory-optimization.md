# 图标内存管理

桌面分组与所有文件夹来源使用同一个有界 CPU 像素去重池（`app/src/pane/image_pool.rs`）。相同像素可跨桌面分组和文件夹映射共享，减少重复分配。

- 以尺寸和像素内容计算哈希，命中后再逐字节比较，避免哈希碰撞替换图像。
- 池最多保留 4096 条弱引用，不延长像素数据的生命周期；容量耗尽时仍正常加载图片。
- 工作线程在锁外计算哈希，不持有文件夹缓存锁进入共享池。
- 同一图像共享 `Arc` 后，也能复用 UI 线程中按源地址索引的缩放像素缓存。GPU 位图仍由各渲染上下文管理。
- 文件夹缓存按 `Vec::capacity()` 计算像素预算，包含已预留但未使用的空间；重复引用继续保守计费，不放大原有缓存上限。

## 验证范围

自动测试覆盖跨线程、独立文件夹缓存及桌面分组的共享、单项刷新隔离、最后一个持有者释放、哈希碰撞及池容量上限。16 个独立线程加载相同的 128×128 BGRA 图像后，只保留一份 65,536 字节像素，独立存储则需要 1,048,576 字节。这是像素分配量，不是进程工作集或 Private Bytes 的实测降幅。

```powershell
cargo test -p luciddesk --bin luciddesk --offline -- --test-threads=1
cargo check --workspace --all-targets --offline
```

实际收益取决于相同图标在多个来源中的重复程度。不同内容的缩略图不会因此减少；大目录的全部已加载缩略图仍由项目列表持有，现有文件夹 LRU 上限也不等于进程总内存上限。
