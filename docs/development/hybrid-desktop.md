# 混合桌面与成员同步

更新：2026-09-12。模块边界见[架构说明](architecture.md)，本页说明数据与显示如何保持一致。

## 成员身份

分组保存 Shell 项目的身份与归属，不保存列表索引作为身份。文件系统项目可以携带卷和文件 ID，虚拟项目使用 Shell 解析名；缺少稳定 ID 时仍存在路径匹配。

排序、删除和 Explorer 刷新会改变索引，即使项目数量相同也必须核对顺序。重名项目不能仅通过显示名称重新定位，应等待控制端完成身份核验。

## 收纳与发布

- OLE `IDropTarget` 接收桌面 Shell 项目，包括虚拟项目；收纳返回引用效果，不要求移动源文件。
- 已收纳项目继续存在于 Shell 清单，Hook 过滤其桌面绘制、命中和选择，面板负责显示。
- 未收纳项目按显示器补齐原生网格空位；移动面板不逐帧移动 Explorer 文件或永久坐标。
- 布局通过有数量边界和名称校验的批次发布。过期索引触发重新获取身份和重试。
- 图标加载失败时保留其原生桌面呈现，避免项目无法访问。

## 刷新与一致性

显式操作、排序和 Shell 通知触发及时同步。定期后台检查只比较 Explorer 项目标识（PIDL）、图标尺寸、间距和 DPI，并核对布局基线；检测到变化时才读取完整快照，避免空闲时每秒逐项打开桌面文件获取文件 ID 和元数据。无变化时保留必要的场景重发以修复 Explorer 内部呈现状态。

后台检查由一个常驻 STA 线程执行，复用 `IShellWindows` 对象，避免每轮创建 COM 对象产生额外读取。每轮重新获取当前桌面视图；查询失败后释放缓存，下次检查重建连接。请求最多只有一个在途，退出时通过关闭通道结束线程，并在 COM 反初始化前释放对象。

初始图标批次完成后再协调后续刷新，避免旧批次覆盖新图像。只有像素变化才替换缓存与 GPU 位图。回收站额外订阅命名空间通知，并按实际空满状态提取系统图标。

具体选择时序见[选择与刷新时序](selection-latency.md)，菜单例外见[图标菜单与重命名](pane-item-rename.md)。

## 退出与验证边界

退出、控制窗口消失或控制进程终止时撤销映射，恢复原生显示。恢复的是运行期映射，不代表可以复原 Explorer 自身重启前的全部历史位置。

回归应覆盖同数量排序、重复名称、跨屏补位、拖入拖出、菜单临时选择、隐藏尾部插入和退出恢复。独立控件测试可以验证几何与消息，不等同于真实 Explorer 拖放结果。
