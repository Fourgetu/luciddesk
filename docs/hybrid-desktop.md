# 自绘 pane 与原生桌面混合模式

运行：`target/debug/lucidpane.exe --hybrid-desktop`。需要同目录中的
`desktop_hook.dll`；配置暂时沿用 `hook-desktop.db` 中的分组归属。
旧全桌面自绘模式和旧原生分组模式保留为显式的独立实现，混合模式不调用全桌面隐藏开关。

## 分工

- pane 复用 `preview` 的 Direct2D/DirectComposition 渲染、图标缓存、材质、
  菜单、折叠动画、自动收起和窗口吸附。移动 pane 不再逐帧移动 Explorer 图标。
- Explorer 继续绘制未收纳项目。Hook 跳过已收纳项目的绘制和命中，过滤桌面选择，
  把未收纳项目映射到每个显示器上连续的原生网格位置。Windows 自动排列设置保持不变。
- 隐藏不会删除 Shell 项目，也不修改文件路径或文件隐藏属性。Shell 项目总数仍包含
  已收纳项目。退出、控制窗口消失或控制进程终止时撤销映射并恢复原生显示。
- 使用 OLE `IDropTarget` 接收桌面 Shell 项目，包括虚拟项目。收纳仅建立引用，返回
  link 效果，不要求 Explorer 移动源文件。pane 内拖动复用已有实现，拖回桌面取消归属。
- Explorer 托管图标菜单期间有明确的临时选择许可；菜单关闭后重新隔离隐藏项目。

## 排序与一致性

图标索引不作为持久身份。监听原生排序/列表变化，并定期核对完整项目顺序和原生位置，
即使项目数量没有变化，也重新匹配分组身份。布局以一次有名称校验的事务发布；
如果索引已经过期，刷新身份映射后重试。定期重发相同场景用于恢复未产生公开通知的
Explorer 内部刷新，相同场景不主动重绘整屏。

旧实现的实际失败记录：切换排序后图标重新出现，随后拖回触发
“原生视图拒绝分组布局，项目或可用空间可能已变化”，错误处理结束应用（退出码 0）。
这不是已确认的进程崩溃。修复增加了同数量顺序核对、排序消息失效处理和拒绝后的重试。

## 验证

- 单元测试覆盖跨显示器补位、首位/中间空位、恢复以及同数量排序后身份归属。
- `geometry_probe` 使用独立原生 owner-data ListView，验证补位后的命中、隐藏项目
  不参与全选/直接选择、菜单临时选择恢复、尾部格子清空与 detach 后的原生几何恢复。
- `hook_probe --geometry --watchdog` 验证独立跨进程事务、错误请求不部分发布、
  控制窗口销毁后的 watchdog 恢复。该测试的耗时不是实际桌面帧率。
- 实际桌面检查保留了自动排列；首次用户验证确认拖入正常，随后暴露上述排序/拖回问题。
  最新修复的真实桌面结果需要继续验证，不以编译成功代替用户界面验证。

## 当前边界

### 自定义材质与主题

云母及云母 Alt 使用系统模糊壁纸画刷叠加自定义色调，Alt 的色调遮罩更弱，保留更多壁纸色彩。
这不是完整原生 Mica 控制器，不依赖 Windows App SDK。亚克力继续使用 HostBackdrop 画刷。
合成材质不读取窗口焦点，不会因为切换到其他程序而主动回退；系统合成不可用时仍保留可读的纯色背景。
每个 pane 可选择跟随系统、浅色或深色；菜单、标题和标签随主题调整，图标位图保持原色。
主题保存于 schema 8 的 panel_theme 表，旧配置默认跟随系统。
pane 默认固定底层，菜单中的“始终置顶”单独保存，不影响材质状态。

Hook 仍要求经过校验的具体 comctl32 版本。原生图标布局映射不写入 Explorer 的永久坐标。
pane 内自绘外观不宣称与 Explorer 像素级 1:1。
Hook 在原生绘制前使用已验证且无重名歧义的显示名称缓存维持隐藏，并读取底层原生网格，
在同一次绘制前按显示器补齐空位，再通知控制器核对完整 Shell 身份。
用户已确认排序不再短暂显示收纳图标；随后报告的空位问题已增加同步补位和原生控件回归测试，真实桌面待复测。
重名项目不能仅凭显示名称重新定位，需要控制器完成身份核对。
图标加载失败时保留其原生桌面显示。新的双向 OLE 文件拖放到其他应用不在此次实现范围内。
