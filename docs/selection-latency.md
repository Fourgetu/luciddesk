# 图标选中延迟

本机 81 项桌面的单次完整清单读取实测约 100–175 ms。此前无变化时也约每秒在 pane UI 线程执行两次完整清单读取，加上坐标查询，使点击和绘制等待，持续的跨进程调用也占用 Explorer。

- 普通 pane 选择清理由同步请求改为异步消息，保留所有者校验、前台进程校验和菜单保护，避免延迟消息影响用户已返回桌面后的选择。
- 反向清理由 Hook 的桌面按下/首次按键事件触发，向隐藏控制窗口投递 `DESKTOP_INPUT_MESSAGE`，携带 `GetMessageTime` 事件时间，清除所有 pane 的选择与焦点显示。只重绘有变化的 pane，不扫描图标，不处理鼠标移动或按键自动重复。发送端跳过 pane 菜单会话；接收端核验桌面 HWND、菜单状态以及事件是否晚于最近的 pane 输入，以兼容首次按下先于桌面激活的时序，同时拒绝陈旧通知。时间比较处理 32 位计数回绕；嵌套回调暂时借用模型时保留通知，由已有 UI tick 重试，不另加定时器。重命名仍由编辑框自己的失焦处理提交，通知不修改编辑目标。
- 定时清单核对移到独立 STA 工作者，最多一个在途任务；每八项暂停 1 ms，让 Explorer 有机会处理输入。
- 工作者只检测变化，不提交布局。清单、修改时间及原坐标发现差异后，继续执行既有同步双清单验证，再发布布局。
- 显式操作、变更通知、排序校验、自动排列和拖动坐标算法保持原有处理。无变化时仍保留周期性重新发布，修复 Explorer 内部显示状态刷新。
- 工作者结果不在按住鼠标或原生菜单期间消费。关闭程序后，晚到的只读结果随接收端释放而丢弃。

验证：混合布局的同数量排序、身份归属、跨屏紧凑排列和同步时机测试通过；几何探针覆盖首次直接拖动、79 项命中、隐藏项选择及尾部/换列插入边界。
